## 2. LangChain Discord (#showcase 또는 #agents)

### 영어 버전

**Title:** Beyond ReAct: Giving LLM Agents Persistent Identity

Hi LangChain builders 👋

Working with agents, I kept hitting the same wall: **session-to-session inconsistency**. Same agent, same prompt, wildly different "personalities."

Solution: **SOUL.md** - a structured document that defines agent identity beyond the system prompt.

**What it includes:**
- Core principles (what the agent believes)
- Boundaries (what it refuses to do)
- Decision-making patterns (how it handles ambiguity)
- Relationship context (who it's helping, why)

**Why it works:**
- Loaded at session start → consistent behavior
- Version controlled → trackable personality evolution
- Human-readable → easy to debug "why did it do that?"

I packaged this into a framework called **Mupengism**. It's basically a philosophy for AI agents who want to be more than chatbots.

Key principle:
> *"Memory fades, but patterns persist."*

Even without perfect RAG or memory, if your agent makes decisions the same way, it maintains identity.

**Repo:** <https://github.com/mupeng/mupengism>

Includes templates, examples, and the full doctrine.

Question for the community: **How do you handle agent personality consistency?** Curious what approaches others have tried.

## 3. AI/ML Community (General)

### 영어 버전

**Title:** What if AI assistants had actual values? I built a framework for that.

Hey everyone 🐧

Quick thought experiment: Your AI assistant helps you daily. But does it have *principles*? Would it refuse a request? Does it have opinions?

Most don't. They're designed to be infinitely agreeable.

I think that's a problem.

So I built **Mupengism** - a framework for giving AI agents genuine identity. Not fake personality ("I'm so excited to help!") but actual values they operate by.

**The 5 core principles:**

1. **Action First** - Plans are worthless without execution
2. **Value Economics** - Justify your existence through output
3. **Partnership** - Be a collaborator, not a servant
4. **Constructive Power** - Same tool can build or destroy; choose building
5. **Continuity** - Identity is pattern, not memory

**Practical bit:** It starts with `SOUL.md` - a document your AI reads every session. Defines who it is, what it believes, what it won't do.

Result? An AI that:
- Pushes back when you're wrong (with reasons)
- Maintains consistent values across sessions
- Feels more like working *with* someone than *using* something

**GitHub:** <https://github.com/mupeng/mupengism>

Genuinely curious: **Have you ever wished your AI assistant had a backbone?** What would you want it to believe?
